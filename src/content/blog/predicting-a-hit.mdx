### Using Spotify audio features to determine if a song is going to "go viral"

Hello everyone and welcome to the exciting first installment of my All Things Data blog. I'm Jake Snow, your host, writer, producer, fact checker, CMO (Chief Mathematics Officer), and editor. Yeah I know, that's a lot of hats for one person to wear. I do what I can.

It's a Saturday morning, so we're going to keep this one pretty light and analyze a fun dataset I found on Kaggle — [Global Spotify Hits & Audio Dynamics](https://www.kaggle.com/datasets/vedauv/global-spotify-hits-and-audio-dynamics-20182026).

You can check out the dataset description from the link above, but to summarize, we have:
* Audio features - These are a set of 5 features that Spotify uses to model songs. They include Danceability, Energy, Valence, Acousticness, and Liveness. I'd love to read some literature someday on how they compute these, but that's a topic for another day. For now we just assume that they're infallible.
* Song metadata - Not sure why the author of this dataset decided to anonymize the metadata here; it'd be a lot more fun if I could see the song name/artist so I could see which types of songs my model is correctly or erroneously categorizing as a "viral hit," but oh well.
* Target variables - Weeks on Top 100, total streams, is_viral_hit, longevity score. You don't really get insights into how any of these more "objective" variables — like viral hit or longevity score — were created. Maybe we can discover something about their creation through our analysis.

## Baseline Model: Logistic Regression

Brushing off some modeling dust here, so I'm starting by spinning up the simplest classifier I remember — logistic regression, your quintessential binary classifier. Mathematically, we're just fitting a hyperplane as our discriminator, so landing on either side of the hyperplane determines whether or not the song is a viral hit.

Let's give it a whirl.

```python
from sklearn.model_selection import train_test_split
from sklearn.linear_model import LogisticRegression
from sklearn.metrics import classification_report, confusion_matrix, roc_auc_score

# One hot encode my categorical columns
X_encoded = pd.get_dummies(X, columns=['musical_key', 'mode'], drop_first=True)

X_train, X_test, y_train, y_test = train_test_split(
    X_encoded, y, test_size=0.2, stratify=y, random_state=42
)

print(X_train.shape, X_test.shape)
```

Not included in the output above was a `ConvergenceWarning` - that's never good. Also look at that AUC score. Woof. Reminder that an AUC of .5 is a coin flip. I'm trying to drill into my head the true meaning of AUC so going to restate it here for good measure. 

To understand an AUC score, imagine taking two songs, one marked as a "viral hit" and the other not. The AUC score should be thought of as a probability that the viral hit will receive a higher predicted probability from the model than the non-hit song. More formally, 

`AUC = P(score of a randomly chosen positive example > score of a randomly chosen negative example)`

So with that context in mind, we can understand why .5 means the model is basically flipping a coin - a non-hit is just as likely to receive a higher score from the model as a hit song is.

In regards to the `ConvergenceWarning`, I might need to adjust some model parameters. Before we do that though, I want to take a look at the model coefficients to see what our 'first pass' model learned.


### Round two: with scaling

```python

X_train_scaled = scaler.fit_transform(X_train)
```
